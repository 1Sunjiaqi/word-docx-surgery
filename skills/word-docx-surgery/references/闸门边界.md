# 闸门边界：它只看得见"被表示出来"的东西

闸门有没有用，取决于两件事：**规范文本覆盖了哪几类改动**、**部件比对比的是什么**。
下面每一条都是实测打出来的（部分来自独立复核的对抗样本），不要凭直觉假定。

## 1 必须被表示出来的改动

| 类别 | 表示方式 | 不表示的后果 |
|---|---|---|
| 文字内容 | 规范文本里的正文/格文本 | 改字看不见（最基础） |
| 段落属性 | `pStyle / numPr / pageBreakBefore / keepNext / cantSplit` | "把某格列表换个编号实例"看不见 |
| run 级字符格式 | 每段/每格的 `runs=` 个数 + `rpr=` 指纹 | 把一个 run 加粗变红看不见 |
| 空格的宽窄 | `norm()` 先把 `U+3000` / `U+00A0` 换成 `<U+3000>` / `<U+00A0>` 再折叠空白 | 半角空格换全角看不见（Python 的 `\s` 也匹配 `U+3000`） |
| 部件内容 | `part_map()` 存 `(size, sha256)`，`part_changes()` 按内容判等 | **只比长度 = 对等长改写完全失明** |

等长改写的对抗样本证明：只比较 `file_size` 会漏掉大量真实变化，尤其是页眉、页脚、属性
和其他独立 XML 部件。现在 `part_map()` 同时保存 `(size, sha256)`，等长改写会打印
`<== 长度相同，仅内容不同`。

## 2 "文本没变就不许动一个字节"

这是一条硬规则，而不是洁癖。如果 `docx_fill.py` 对每个目标段落都重写，即使文本完全相同，
也会把原有 run 结构拍平；这是真实变化，不能算作 no-op。现在只有文本确实变化时才进入
编辑路径。

判定标准：`docx_fill.py` 的报告要能分别说出 `paras_noop`（一字节未动）、`paras_keep`（段内编辑、
保留原 run 切分）、`paras_flat`（整段重写、收敛到首 run）。后两项必须是**有意为之**的。

## 3 只读约束：基线不许篡改，外部改动显式登记

开工前用 `make_baseline.py` 给项目目录拍一张 `(mtime, 大小, 相对路径)` 基线，
收工用 `verify_readonly.py --base <目录> --tsv <基线>` 复验：

- **不要为了让自检变绿而改基线。** 基线的全部价值就在于它是"开工前"的诚实记录。
  `make_baseline.py` 因此**拒绝覆盖**已存在的基线（要重采必须 `--force`）。
- 确实发生了非本任务造成的改动（例如外部编辑器再次保存了文件）时，走**登记**：

  ```powershell
  python scripts/verify_readonly.py --base <目录> --tsv <基线> --ack <已登记外部改动.tsv>
  ```

  登记表逐行写：`<相对路径> \t <期望的新字节数> \t <谁在何时改的、改了什么、证据在哪>`。
  登记过的从失败项里剔除并单独打印；**没登记的、以及登记后大小又对不上的，照样失败**。

## 4 闸门管不到的地方

- **管不了语义。** 改动清单能证明"只有这一格变了"，不能证明"这一格填对了"；
- **管不了判断类决策。**"这个用例算不算通过"不该由执行者替你定；
- **`docx_textconv.py` 只能看、不能打补丁。** 它给 git 提供可读 diff；回滚靠整份文件的 blob；
- **仍然需要一个看懂版面的人。** 联系表把全部页面摊在一张图上，但"续表位置对不对"最终由人确认。

## 5 出现新改动类别时的自检动作

新增域、书签、批注、内容控件、图片、样式等类别时：

1. 造一个**只有这一类改动**的副本；
2. 跑 `docx_ledger.py`，看它报不报、报的位置能不能对上；
3. 如果不报 —— 先补表示（规范文本或部件比对），再动真文档。

`scripts/selftest.py` 把这条自检固化成了断言：A 正文改字 / B run 级格式 / C 空格宽窄 /
D 等长部件 / E 格内编号 / F 定位式最小替换（含"被拆成多 run 就如实报未找到"）/
G 只读自检（含"登记后又被改仍然失败"与"基线拒绝覆盖"）。
