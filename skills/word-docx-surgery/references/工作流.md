# 工作流细目

入口与两道闸门见 `SKILL.md`；闸门能力见 `闸门边界.md`；运行环境见 `环境事实.md`。
下文 `scripts/` 指本 skill 的 `scripts/` 目录；`python` 指已安装依赖并准备执行脚本的解释器。

## 0 开工前先把"做完"的判定写下来

先写一份 `验收标准_<任务>.md`，表头固定为四列：

| # | 验收标准 | 验证方式（可执行命令或可复算的量） | 本次结果 |
|---|---|---|---|
| 1 | 原件未被改动 | `verify_readonly.py --base <目录> --tsv <基线>` 退出码 0 | 待填 |
| 2 | 只改了申报的位置 | `docx_ledger.py 基线 候选 --allow <白名单>` 退出码 0 | 待填 |
| 3 | 改动内容来自独立目标稿 | 从目标稿独立推导一遍，逐格比对命中数 | 待填 |
| 4 | 与验收对照稿逐格一致 | 逐格文本比对，差异逐条归因 | 待填 |
| 5 | 版面与预期一致 | `render_qa.py --compare` 的页数与变化页 | 待填 |

三条写法要求（都是被独立复核打回来过的教训）：

1. 每条都要附**能跑的命令**或者**可复算的量**（sha256、页数、逐格推导命中数）；
2. 结果栏写**实测数字**。"✅"不是数字，写不出数字就说明这条还没验。
3. **不要声称"全部一致"**，除非你刚刚跑过、退出码是 0、且知道期间没有第三方动过文件。
   文件可能在验证后又被外部编辑器保存。正确写法是"截至验证时刻一致"，并单独说明
   之后发生的外部改动，不要把过期结论写成永久状态。

## 1 冻结节点（一个项目只做一次）

```powershell
cd <项目目录>
git init
git add -A
git commit -m "baseline: 原始资料"
git tag baseline
```

原件（母本、交付件、目标稿）进这个 commit。此后**任何**改动都发生在支线上，
要退回随时 `git diff baseline` / `git restore`。

## 2 开一条支线（一个任务一条）

```powershell
git worktree add <目录> -b task/<任务名> baseline
```

`git worktree` 的语义是"**同一个仓库多开一个目录 + 一条独立分支**"，不是复制文件夹：
所有工作树共享同一个 `.git` 历史，所以 tag、diff、回退都是同一个体系。

- 一个任务 = 一棵工作树 + 一条分支，彼此不污染；
- **节点用 tag 表达**（`baseline` / `task-X-v1` / `task-X-v2`），不要用文件名表达版本。
  同类文件名的副本一旦散落，交付件和中间稿会很快失去可追溯性。
- 让另一个会话干活时，任务卡里写清"从哪个 tag 出发、在哪棵工作树里改"。

## 3 先看结构，别急着改

```powershell
python scripts/docx_textconv.py 目标.docx > 结构.txt      # 表按出现顺序编号 TBL#k，格是 rXXcYY
python scripts/docx_min_edit.py 目标.docx --find "某句话" --dry-run
```

- `docx_textconv.py` 的输出是"规范文本"：删掉了 rsid/paraId 这类每次保存都变的东西，
  所以差异里出现的每一行都对应一次**真实**改动；
- `--dry-run` 报出这句话在 `word/document.xml` 里连续出现几次。
  命中 0 次不代表不存在，通常是被 Word 拆成了多个 run（见第 5 节的应对）。

## 4 先做样本，再批量

```powershell
python scripts/docx_min_edit.py 副本.docx --find "旧文字" --replace "新文字" --occurrence 1 --out 样本.docx
python scripts/docx_ledger.py 基线.docx 样本.docx --allow "TBL#1 > r03c01"
python scripts/render_qa.py 样本.docx --out qa_样本
```

把这两个结论交给人确认，再动批量。**永远不用 `--all` / 全文替换**：
一次全文替换可能把大量无关位置一并改掉，而执行者仍然以为只改了一处。

## 5 另一种任务：往空白格/指定段落里填内容

先把要填什么写成**规格文件**（JSON），再一次性填，不要手工逐格敲：

```json
{"cells": [{"table": 21, "row": 2, "col": 1, "paras": ["第 1 段", "第 2 段"]}],
 "paragraphs": [{"anchor": "锚点子串", "text": "整段新文本"}]}
```

```powershell
python scripts/docx_fill.py 副本.docx 规格.json --out 产出.docx --dry-run
python scripts/docx_fill.py 副本.docx 规格.json --out 产出.docx --restart-lists
```

三个必须知道的语义（v2 修复后的行为）：

- **文本没变就一个字节都不碰**（v1 会把每个目标段落重写一遍，把文本本来就相同的段落也拍平，
  那是真实发生的改动，闸门当时却看不见）；
- **段内编辑保留原 run 切分**（把多 run 段落合成 1 个 run，会让数字继承首个 run 的字体，
  在渲染里表现为真实的字形错位）；
- **整段重写才收敛到首个 run**；`--restart-lists` 用于重置格内列表编号（会改 `numbering.xml`，
  这是**应该申报**的部件改动，不是噪声）。

## 6 收工：两道闸门 + 只读自检

```powershell
python scripts/docx_ledger.py 基线.docx 产出.docx --allow <白名单> --json 清单.json
python scripts/render_qa.py 产出.docx --compare qa_样本/manifest.json
python scripts/verify_readonly.py --base <项目目录> --tsv <基线.tsv>
git add -A && git commit -m "改了什么、改在哪张表哪一格"
```

白名单要能从"改动清单"反查到"原始要求"。收窄白名单跑一次（故意让它失败），
确认**闸门真的会咬人**：如果收窄之后还报通过，那是闸门坏了，不是改动干净。

## 7 交付

交付 = 三样东西：**改动清单**（哪几张表哪几格、旧文新文逐条）、**渲染结论**
（页数、"有变化的页"列表、联系表图片）、**未做与不确定**（留 `TODO：` 或 Word 批注）。
"已完成"三个字不是交付。

目录约定：中间产物进 `_work/` 或工作树目录，**交付目录只放交付物**；
文件名不许出现" - 副本"、"版本1/版本2"。

## 禁止清单（每条都对应一次真实事故）

| 禁止 | 当时的后果 |
|---|---|
| 全文替换 / `--all` | 一次替换可误改大量无关题注 |
| 顺手加没要求的排版设置 | 擅自增加与下段同页等设置，产生来源不明且未解释的版面变化 |
| 动目录域或目录样式 | Word 重排目录时可能替换条目样式、改变字号与缩进并引起分页变化 |
| 发明内容（日期 / 编号 / 结论 / 截图） | 执行者自行补写日期、表号、结论或证据，交付前必须整段回退 |
| 用文件名做版本管理 | 多个同名副本散落，无法确认交付件 |
| 拿没渲染过的文档当最终版 | 表格断页、页眉页脚和图片缩放没有经过真实渲染确认 |
| 依赖不可用的转换链 | 目标环境没有对应工具时，流程会在转换阶段直接失败 |
| 改了 `numbering.xml` 之类的部件却不申报 | 闸门一会报 `PART word/numbering.xml`；这是应申报的改动，不是噪声 |

不确定的内容怎么办：**留 `TODO：` 或写进 Word 审阅批注**，交给人定，不要替人决定。

## 已知失败模式与应对

| 现象 | 原因 | 应对 |
|---|---|---|
| `docx_min_edit.py` 报"未找到连续文本" | Word 把一句话拆成多个 run，整句在 XML 里不连续 | 先用 `docx_textconv.py` 看清 run 切分，改用 `docx_fill.py` 的段级替换或按 run 定位 |
| Word 报"文件似乎已损坏" | 用 ElementTree 改完 OOXML 后丢了根标签上的 `xmlns` 声明 | 序列化后把缺失的 `xmlns:*` 补回（`docx_fill.py` 的 `preserve_root_namespaces()`），见 `环境事实.md` |
| 渲染出的页数比 Word 里少/多 | 没有更新域或没有重新分页 | `render_qa.py` 默认做 `Fields.Update()` + `TOC.Update()` + `Repaginate()`，别用 `--no-fields` 跳过 |
| 页面出现轻微字形错位 | 段落 run 结构被拍平，数字继承了别的 run 的字体 | 段内编辑保留 run 切分；改完重跑 `render_qa.py` 定位变化页 |
| 部件"看起来没变"但 Word 里行为变了 | 只比了文件长度，等长改写看不见 | `part_map()` 存 `(size, sha256)`，见 `闸门边界.md` |
